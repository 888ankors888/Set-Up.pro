# Задача №6: контракт слоя данных

Статус пакета 2: общий модуль подключён только к workouts.html и workouts/store.js. В index.html, питании, анкетах, привычках и импорте прежние пути записи ещё не заменены. Задача №6 остаётся открытой. Это описание кандидата; интеграция должна пройти согласование, CI и браузерную проверку.

## API общего модуля
- `createStore({storage, validate})`: обязательны явно переданное хранилище и синхронный доменный валидатор.
- `read() -> {raw, state}`: чтение без записи. Отсутствующий ключ возвращает null; повреждение, отказ доступа и ошибка валидации различаются кодами ошибок.
- `commit(next, snapshot)`: проверяет состояние и исходный снимок, пишет только `nt1`, затем уведомляет подписчиков. Явная первичная инициализация возможна через снимок отсутствующего ключа; автоматической нет.
- `update(change)`: перечитывает состояние, изменяет независимую копию синхронным mutator, затем вызывает commit. Callback возвращает undefined.
- `subscribe(listener) -> unsubscribe`: независимая копия для каждого подписчика. Исключение UI не превращает успешную запись в ошибку сохранения; количество ошибок возвращается в listenerErrors. Вложенные записи при уведомлении запрещены.
- `attachStorageEvents(window) -> detach`: реагирует на nt1 и clear; перечитывает хранилище вместо доверия payload события. Обработку ошибок внешнего обновления интерфейс должен определить при дальнейшей интеграции.

## Подключение тренировок
workouts.html синхронно загружает data-store.js перед workouts/store.js и workouts/page.js. В CommonJS workout store использует require('../data-store.js'). При отсутствии зависимости запись не разрешается; резервного прямого писателя нет.

Существующий API FoodWorkoutsStore сохранён. read и write используют общий адаптер; commitDay продолжает вызывать write. Валидация схемы workouts сохранена. На этом этапе валидатор проверяет корневой объект и workouts, но НЕ является полным валидатором питания, анкет и других разделов. Совместимые неизвестные JSON-поля сохраняются.

Обычная работа тренировок не вызывает activateLegacyReset. Существующий явно вызываемый метод сброса сохранён для совместимости, а его запись nt1 проходит через общий адаптер; последующее удаление food.pro.workouts.v1 по-прежнему отдельная, неатомарная операция. Этот метод не разрешается вызывать без отдельного согласования. Локальные тесты вызывают его только на искусственном хранилище.

Текущий workouts/page.js не меняется: существующие обработчики storage/focus и вывод ошибок сохранены. Общая подписка attachStorageEvents пока туда не подключена. Питание, анкеты, привычки и импорт остаются отдельными писателями; их взаимодействие с тренировками требует дальнейшего переноса и проверки.

## Ограничения
Сравнение raw обнаруживает уже изменившийся снимок, но не является атомарной транзакцией между вкладками. Остаются гонки между сравнением и записью и ABA-сценарий. Нельзя обещать отсутствие потерянных обновлений до реализации и браузерной проверки общей политики координации всех писателей.

JSON-совместимость проверяется до сериализации: NaN, Infinity, undefined, функции, Date, разреженные массивы и циклы отклоняются, а не теряются молча. Неизвестные JSON-поля сохраняются; правила совместимости и поддерживаемые версии определяет validate.

Ключи темы обычным сохранением не затрагиваются. Модуль не меняет глобальное S и не показывает toast. Ошибки адаптера в workout store получают сообщения на русском и сохраняют поле code.

## Проверки
`node --test tests/data-store.test.cjs workouts/tests/store.test.cjs tests/workouts-data-layer.test.cjs`

Локально проверяются 27 тестов адаптера, 8 существующих тестов тренировок и 10 интеграционных тестов. Изолированный VM-тест проверяет загрузку браузерных глобальных объектов, а не отрисовку интерфейса. CI отдельно проверяет импорт, сборщик и полную сборку. Результаты CI и браузера не следует считать пройденными только по наличию workflow.
