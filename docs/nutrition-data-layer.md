# Дневник питания: кандидат подключения к слою данных

Пакет 3 задачи №6. База подготовки — refactor/data-layer на 68cb437. Пакет не закрывает задачу №6.

## Что меняется
nutrition-store.js использует общий data-store.js и сохраняет ключ nt1. append дописывает записи в перечитанное состояние, не подставляя старый S целиком. remove требует неизменённую ожидаемую запись. До записи проверяются даты, время, тип приёма пищи, непустое имя, конечные неотрицательные КБЖУ/масса, строковые уникальные ID. Будущая дата запрещена при добавлении; существующая история не удаляется и автоматически не исправляется. Проверка полей estimate_range и прочих дополнительных метаданных ограничена JSON-совместимостью, это не полная доменная валидация этих расширений.

В index.html переводятся addEntry, manualSave, основной jPut, каталог выбранной даты, meSave и delEntry. S и интерфейс обновляются после успешной записи. Метаданные ИИ, нулевая неизвестная масса, существующие ID и другие разделы состояния сохраняются. Общий модуль и репозиторий подключаются синхронно перед первым встроенным скриптом. Стили и разметка интерфейса не меняются.

## Применение исходника
scripts/migrate-nutrition.py принимает только исходный Git blob 67352cb0ee79e7c7f2107dc4aa45b89ee523175d либо уже подготовленный ef90753574010d0ddce102496cd4b2bd19358cda. Неизвестный исходник останавливает применение до записи. Повторное применение к целевому исходнику ничего не меняет. Это изменение кода, не миграция и не очистка пользовательских данных.

Workflow data-layer-check сначала готовит исходник, затем запускает тесты и сборку. Только после успеха он может записать изменённый index.html в ту же ветку. Наличие коммита пакета не означает, что итоговый исходник уже применён: требуется проверить отдельный автоматический коммит и результаты CI. Публикации и слияния нет.

## Что НЕ перенесено
Общий save(), импорт/экспорт резервной копии, анкеты, вода, привычки и старые спортивные записи остаются на прежних путях. Альтернативный backend/public-text.js не изменён; это резервный ввод, не подключаемый текущим /app при наличии MEAL_ESTIMATE_API. Отчёты, питание и прочие разделы не должны считаться полностью мигрированными по одному репозиторию. Остаются гонки между проверкой снимка и записью, а также другие старые писатели. Это не атомарная синхронизация вкладок.
