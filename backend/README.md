# food.pro — backend GigaChat

Backend на FastAPI: разбор описания еды, приблизительная оценка КБЖУ по тексту и фото, отчёты по дневнику и черновик плана активности. Ответы модели проверяются схемами Pydantic; это не подтверждает точность распознавания или рекомендаций.

Документ описывает код ветки рефакторинга. Он не подтверждает, что эта версия опубликована на Render.

## Маршруты

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health` | Статус приложения и наличие настройки GigaChat |
| POST | `/api/food/parse` | Продукты и уточнения из текста, без вычисления КБЖУ |
| POST | `/api/food/estimate` | Приблизительные диапазоны КБЖУ блюд и общий итог |
| POST | `/api/food/estimate-photo` | Оценка еды по фотографии |
| POST | `/api/reports/analyze` | Отчёт по неделе или месяцу |
| POST | `/api/reports/day` | Комментарий по приёму пищи и совет по дню |
| POST | `/api/reports/combined` | Объединённый отчёт по питанию и активности |
| POST | `/api/sports/plan` | Черновик плана активности с проверкой ограничений |
| GET | `/api/models` | Список моделей; требуется Bearer-токен |
| GET | `/app` | HTML-интерфейс из корневого `index.html` |
| GET | `/public-text.js` | Вспомогательный текстовый интерфейс |
| GET | `/photo-input.js` | Вспомогательный интерфейс загрузки фото |

Форматы запросов определены в моделях соответствующих Python-модулей. Для текстовых маршрутов еды тело запроса: `{"text":"рис 150 г и два яйца"}`; длина текста — от 2 до 2000 символов, пустое после удаления пробелов описание отклоняется.

## Доступ и ограничения

В текущем коде `APP_ACCESS_TOKEN` проверяется только маршрутом `/api/models`. Маршруты еды, отчётов и плана активности не требуют этого токена. Наличие переменной не делает всё приложение закрытым.

Для `/api/models` передавайте `Authorization: Bearer <APP_ACCESS_TOKEN>`. Не вводите ключ GigaChat в браузер и не публикуйте секреты в GitHub.

Общая проверка квот использует SQLite `/tmp/food-pro-quota.sqlite3`: до 5 запросов с IP за окно 60 секунд и до 100 запросов по суточному UTC-ключу приложения. Окно IP начинается с первого запроса, а не является скользящим. При нескольких процессах или экземплярах нельзя считать эти ограничения глобальными без отдельной проверки общей среды хранения. Хранилище временное, не база дневника.

Генерация текста и обработка фото используют общий семафор на 2 одновременные операции в процессе. Это не общая распределённая очередь. CORS разрешает GitHub Pages владельца и localhost/127.0.0.1 на порту 8000, но не заменяет авторизацию.

Вызовы генерации, включая неуспешные после учёта квоты, могут расходовать лимит. `/health` не проверяет успешность обращения к провайдеру.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `GIGACHAT_CREDENTIALS` | Серверный ключ доступа к GigaChat |
| `GIGACHAT_SCOPE` | По умолчанию `GIGACHAT_API_PERS` |
| `GIGACHAT_MODEL` | По умолчанию `GigaChat-3-Ultra` |
| `GIGACHAT_VISION_MODEL` | Модель для фото; иначе используется `GIGACHAT_MODEL` |
| `GIGACHAT_CA_BUNDLE` | Путь к CA; по умолчанию `russian_trusted_root_ca_pem.crt` |
| `APP_ACCESS_TOKEN` | Пароль только для `/api/models` в текущей реализации |

TLS-проверка включена. `build.sh` устанавливает зависимости, загружает корневой сертификат с `gu-st.ru` и проверяет его чтение через SSL. Ошибка останавливает сборку.

Проверьте выбранную ветку сервиса перед публикацией. Изменения `refactor/code-cleanup` не считаются опубликованными автоматически.

## Локальный запуск и тесты

Из каталога `backend`, в подготовленном Python-окружении:

```bash
bash build.sh
uvicorn main:app --host 127.0.0.1 --port 8001
```

`build.sh` требует Bash, curl и сетевой доступ. Секреты задавайте в окружении вне репозитория. Без ключа серверные операции GigaChat недоступны; статус наличия ключа виден в `/health`.

Запуск существующих тестов из каталога `backend`:

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
```

Тестовые файлы: `tests/test_combined_report.py` и `tests/test_sports_normalization.py`. Эта команда приведена для запуска, а не как подтверждение успешного прогона.

## Фотографии и диагностика

Фотообработчик принимает JPEG, PNG и WebP: до 12 000 000 байт и 25 000 000 пикселей. Изображение преобразуется в JPEG с размером не более 1600 пикселей по каждой стороне перед отправкой провайдеру.

После обработки приложение пытается удалить загруженный файл у провайдера. Удаление не гарантировано при ошибке сети или API. Сообщение `photo_cleanup_failed` фиксирует неудачу удаления без содержимого изображения и ключей. Не удаляйте его как обычный отладочный вывод без альтернативной диагностики.

## Интерфейс и известные ограничения

`/app` читает корневой `index.html`; при отсутствии строки `MEAL_ESTIMATE_API` добавляет подключение `/public-text.js?v=1`. Наличие этого маршрута не подтверждает корректную загрузку всех относительных JS/CSS-файлов.

`public-text.js` зависит от экрана `today`, а `photo-input.js` переключается на него после обработки фото. Совместимость с перенаправлением на дневник требует проверки в браузере. В `photo-input.js` адрес API Render задан явно; локальный запуск backend сам по себе его не меняет.

Дневник сохраняется в браузере, а не в SQLite квот. Backend не предоставляет учётные записи и синхронизацию дневника.
